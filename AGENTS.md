# AGENTS.md - TeaCoder frontend

Instructions for agents (Claude Code and others) working in this repository. `CLAUDE.md` includes this file. Visual style rules live in [DESIGN.md](DESIGN.md) - read it before any UI change.

## Project

An educational platform for web development. Next.js 16 (App Router), React 19, TypeScript strict, Tailwind 3 + reworked shadcn/ui, TanStack Query 5, axios, react-hook-form + zod, next-themes, framer-motion, sonner, lucide-react. Package manager: **bun**. The backend is a separate repository (`../elysia-backend`); the API defaults to `http://localhost:8000`.

## Commands

| Command                           | What it does                                                             |
| --------------------------------- | ------------------------------------------------------------------------ |
| `bun install`                     | install dependencies                                                     |
| `bun run dev`                     | dev server (Turbopack) on `http://localhost:3000`                        |
| `bun run build` / `bun run start` | production build and start                                               |
| `bun run typecheck`               | `tsc --noEmit`                                                           |
| `bun run lint`                    | `tsc --noEmit` + `prettier --check` over `src/**` and `*.ts`             |
| `bun run format`                  | `prettier --write` over **all of `src`** - see the formatting rule below |
| `bun run generate`                | regenerate the API client from `OPENAPI_URL` into `generated/`           |
| `bunx prettier --write <files>`   | format only your own files                                               |

CI (`.github/workflows/ci.yml`) runs typecheck and build on PRs to `main`. CD (`cd.yml`) builds the Docker image on pushes to `main`.

## Before running

- Copy `.env.example` to `.env`. Variables are described in `README.md`.
- Data pages (home, courses, lesson, account) fetch on the server. If the backend is down, the home page fails with `ETIMEDOUT`. **Do not stub data** - ask the user to start the backend. `/about` works for layout checks without the API.
- Before `bun run dev`, check whether port 3000 is taken: the user often runs the server themselves. If the user stopped your server, don't restart it without asking.

## CodeGraph

The repository has a CodeGraph index (`.codegraph/`). Use it **before** grep or reading files when you need to find or understand code:

- MCP tool `codegraph_explore` (pass this repository as `projectPath`): one call returns the source of the relevant symbols with line numbers, call paths and the blast radius (who depends on a symbol).
- From the shell: `codegraph explore "<symbols or question>"`.
- Before changing a shared component or utility (`Button`, `CourseCard`, `getMediaSource`, `formatPrice`...), check its blast radius so you don't break callers.
- Indexing (`codegraph init`, upgrades) is the user's call, not the agent's.

    home/ course/ lesson/ premium/ account/ auth/ consent/ layout/ payment/
    motion/         Reveal and other animation wrappers
    shared/         Logo, Heading, ConfirmDialog, Toaster...
  constants/        routes.ts (all paths come from here), fonts.ts, seo.ts, payment and SSO icons
  hooks/            use-course-progress, use-media-source
  lib/
    api/client.ts   axios client: in-memory access token, silent refresh, orval mutator
    auth/           AuthProvider, session marker, sign-in/out
    consent/        cookie consent (tc_consent)
    analytics/      analytics.* and Yandex Metrica (only with consent)
    captcha/ fingerprint/ webauthn/ courses/ config/

Import aliases: `@/*` → `src/*`, `@/generated/*` → `generated/*`. Prettier sorts imports.

## Rules

### API and data

- The API client is generated by orval: hooks `use<Method><Path>Query|Mutation` and functions `get<Path>Query` (for server components); types in `generated/model`. **Never edit `generated/**`by hand** - only via`bun run generate`.
- Don't change API contracts, error handling, auth, refresh tokens, 2FA, captcha or cookie consent logic unless explicitly asked.
- Don't add features the API doesn't support: reviews, course ratings, instructors, certificates, quizzes, notes, Q&A, search, filters, favorites, lesson durations, student counts.
- New routes only on the user's direct request. Paths always come from `ROUTES` in `src/constants/routes.ts`.
- Platform settings (captcha, social providers, payment methods, subscription prices, currency, storage URL) come from `GET /`: `getAppConfig()` on the server, `useAppConfig()` on the client. Never hardcode them.
- Prices go through `formatPrice(amount, currency)`. Storage images go through `getMediaSource()` / `useMediaSource()`.

### Analytics

Don't touch, move or rename `analytics.auth.*` calls or event names. Metrica loads only when `consent.analytics === true`.

### Code

- TypeScript strict, no `any`. Types come from `generated/model`.
- Prettier: tabs, single quotes, no semicolons, width 80, sorted imports and Tailwind classes.
- Comments in English, only where the "why" isn't obvious.
- UI text in Russian.
- Keep every state: skeletons, empty, error, `isLoading`, `disabled`, toasts (`sonner`).

### Style

Everything about colors, fonts, spacing, buttons, motion and imagery is in [DESIGN.md](DESIGN.md). In short: tokens only (no hex, no `blue-600`), primitives from `src/components/ui`, pill buttons, `Reveal` for section entrances, check both themes at 375 / 768 / 1280 px.

### Formatting

Many older files are not prettier-formatted. `bun run format` rewrites all of `src` and floods the diff with hundreds of unrelated changes. **Format only the files you changed:** `bunx prettier --write <paths>`.

### Git

- Work on a branch from `dev`. Commit and push only when the user asks.
- Commit messages: Conventional Commits in English - `feat(ui): ...`, `fix(auth): ...`, `chore: ...`, `docs(legal): ...`.
- Don't mix redesign, logic and `generated/` regeneration in one commit.
- On Windows, `core.autocrlf=true` can make `git status` show files as modified while `git diff` is empty. Trust `git diff`.

## Verify before handing off

1. `bun run typecheck` passes, and prettier passes on the changed files.
2. For significant changes, `bun run build`.
3. UI changes opened in the browser: light and dark themes, widths 375 / 768 / 1280 px, no horizontal scroll (`document.documentElement.scrollWidth === innerWidth`).
4. Report honestly: what was checked, what wasn't, and why (e.g. the backend was unavailable).
